読み込みと基本の使い方

TurboWarp Plus Editor では、「拡張機能を追加」の TurboWarp-Plus の一覧から読み込みます。ほかの TurboWarp では、「カスタム拡張機能」で https://kubohiroya.github.io/turbowarp-test/dist/turbowarp-test.js を指定し、サンドボックスなしで実行します。失敗したブロックを知らせ、フレームを数えるために、VM に直接触れる必要があるからです。

配布契約はextension-manifest.jsonで確認できます。

テスト [台本の場面数を数える]
  場面を読み込む
  (リスト「場面」の長さ) が (3) と === で等しいことを確かめる

スクリプトをクリックしても動きます。まとめて実行し、状態を毎回もとに戻すのは、TurboWarp Plus Editor のテスト実行器の役目です。

テスト

テスト [NAME]

ハットです。opcode は whentest、引数 NAME は表示用の名前です。緑の旗やほかのイベントでは起動しません。実行器はテストをターゲットとブロックIDで指すので、名前を変えても履歴は切れません。

テストの前に

テストの前に

ハットです。opcode は whensetup です。実行器が作品の状態をもとに戻した後、各テストの前に動きます。スプライトとステージごとに1つまでにします。

=== で等しいことを確かめる

[ACTUAL] が [EXPECTED] と === で等しいことを確かめる

opcode は assert_strict_equals です。型も値もそのまま比べます。文字の "1" と数の 1、"ABC" と "abc" は等しくありません。

Scratch の = で等しいことを確かめる

[ACTUAL] が [EXPECTED] と（Scratch の = で）等しいことを確かめる

opcode は assert_equals です。Scratch の = と同じく、大文字と小文字を区別せず、数として読めれば数として比べます。"1" と "1.0"、"ABC" と "abc" は等しくなります。どちらで比べるかを、ブロックを選ぶことで明示します。

真であることを確かめる

[CONDITION] であることを確かめる

opcode は assert_true です。空の穴は偽です。

誤差以内で等しいことを確かめる

[ACTUAL] が [EXPECTED] と誤差 [TOLERANCE] 以内で等しいことを確かめる

opcode は assert_close です。数として読み、差が誤差以下なら通ります。座標や速さなど、小数の計算結果に使います。

リストが等しいことを確かめる

リスト [ACTUAL] がリスト [EXPECTED] と等しいことを確かめる

opcode は assert_list_equals です。長さが同じで、同じ位置の項目がすべて === で等しければ通ります。リストが見つからなければ失敗します。

フレーム以内に真になることを確かめる

[FRAMES] フレーム以内に [CONDITION] になることを確かめる

opcode は assert_eventually です。条件を1フレームに1回確かめ、真になった時点で通ります。指定したフレーム数を過ぎても偽なら失敗します。秒ではなくフレームで数えるので、コンピューターの速さで結果が変わりません。

条件を確かめ直せるのは、インタープリターで動くときだけです。実行器はコンパイラーを切ってテストを動かします。コンパイルされたスクリプトでは、最初に偽なら、そのことを示して失敗します。

フレーム進める

[FRAMES] フレーム進める

opcode は step_frames です。指定したフレーム数だけ待ち、ほかのスクリプトや動き、クローンを進めます。

真になるまで待つ（上限付き）

[CONDITION] になるまで待つ（最大 [FRAMES] フレーム）

opcode は wait_until_bounded です。条件が真になるまで、1フレームに1回確かめながら待ちます。上限を過ぎるとテストの失敗として記録します。インタープリターについての注意は、上のブロックと同じです。

実行器との約束

確かめるブロックは、結果を1件ずつ VM の runtime にイベント KUBOHIROYATEST_ASSERTION として出します。中身は確かめた種類、通ったかどうか、ブロックID、スクリプトの先頭のブロックID、ターゲットID、フレーム数、実際の値と期待した値です。失敗したときは、そのスクリプトを止めます。

テストを含む作品を配布するとき、テストは不活性のまま残せます。外すときは sb3-toolchain build --strip-tests を使います。
